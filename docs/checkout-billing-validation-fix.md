# 账单填写与结账金额校验修复

日期：2026-11-13

## 故障与证据

失败截图显示可见账单国家仍为 Philippines，填入的却是美国地址和五位邮编；页面提示 `Your postal code is invalid.`，Province 为空。日志此前将原生选择操作的结果当作最终国家值，又在省份缺失时打印“账单地址校验通过”，最后被固定税率推算的金额门槛中止。

## 修复

- 优先操作及回读可见国家控件，支持自定义 combobox；不再信任与可见控件冲突的隐藏 select。原生 select 操作后回读，识别受控组件回滚。
- 校验实际字段值，历史填写成功标记不再替代当前页面内容；空省份、无效邮编、`aria-invalid`、原生 `validity` 和可见错误消息都会中止流程。只读原生有效性，不触发提交或 `invalid` 事件。
- 初次填写后和最终提交前均核验字段；金额更新后再次检查国家和必填字段。
- 读取可见 `Due today` 金额并等待稳定，不把套餐单价、隐藏金额或税额当作应付总额。移除固定 12% 倒推金额的门槛和账单记录兜底；记录本次实际观察到的金额。
- 提交前核对页面币种与任务币种，发生变化时报告错误，不静默改成其他地区或币种。

## 配置边界

正常订阅任务的地区、币种及代理标签仍按套餐确定，账单地址继续由既有地址池选取：

| 套餐 | 代理标签 / Checkout 地区 | 结账币种 |
| --- | --- | --- |
| Go | EG（埃及） | EGP |
| Plus | PH（菲律宾） | PHP |
| Pro 10X | PH（菲律宾） | PHP |
| Pro 20X | PH（菲律宾） | PHP |
| Pro 50X | PH（菲律宾） | PHP |

账单国家从地址记录读取，不用它覆盖任务的 Checkout 地区、币种或代理。找不到匹配国家标签的代理时仍报错。原有后台支付链接调试的显式地区覆盖功能保留。

币种和价格最终由上游 Checkout 返回，测试不证明代理 IP 单独决定价格，也不保证任何地址的税务待遇。
